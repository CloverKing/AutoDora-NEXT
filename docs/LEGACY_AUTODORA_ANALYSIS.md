# AutoDora-V3.4.3.apk（自走铜锣）深度拆解与继承分析

> **分析对象**：`AutoDora-V3.4.3.apk`（包名 `jwo.monkey.autodora`，原生库 `libAutoDora.so` + `libDeviceScanner.so`）
> **分析目的**：提取旧版在长期实战中打磨出的优秀**悬浮窗交互、神魔之塔解盾选项与参数设计**，明确 `AutoDora-NEXT` 应该**保留并升级**的部分与**彻底舍弃**的历史包袱。

---

## 1. 旧版总体结构速览

旧版实际是一款支持 10 款转珠游戏（神魔之塔、PAD、逆转三国等）的 Root 辅助，核心结构由四部分组成：
1. **主界面配置（ViewPager 多标签页）**：一般设定（`page_main`）、转珠设定（`page_orbs`）、神魔之塔专属（`page_tos`）、特殊设定（`page_special`）、截图路径（`page_screenshot`）。
2. **悬浮窗服务（`DoraService` + `window_floating`）**：三态图标、工具条、原地校准条、**游戏内悬浮调参面板**、多候选路线切换与消珠预览条。
3. **符石手动编辑窗（`OrbSetting` + `window_grid` + `window_orb_setting`）**：直接在盘面正上方改珠、涂抹拼图盾/风化/起点/终点，且支持「锁定设定」。
4. **原生 C++ 引擎（`libAutoDora.so`）**：一方面实现核心算路（`solveBoard` + `SODoraConfig` + `SODoraResult`），另一方面直接通过 Root 读写 `/dev/input/event%d` 与 `/dev/uinput` 模拟触控。

## 2. 最值得保留与升级的精华设计

### 2.1 悬浮窗交互设计（实战手感极佳）

| 旧版交互设计 | 具体机制 | AutoDora-NEXT 继承与升级建议 |
| :--- | :--- | :--- |
| **三态主悬浮球** | 待机 / 计算中 / 移动中 切换不同状态图标，可拖动 | **保留**：升级为 Material 3 动态微缩状态球（带计算进度环与当前模式色标） |
| **游戏内原地悬浮调参（`tuning_view`）** | 悬浮条点「调参按钮」直接在游戏画面内展开设置页，不用切出游戏 | **强烈保留**：改为半透明底部/侧边抽屉，战斗中随时切换预设、Combo 盾、直排升华与属性权重 |
| **多候选路径左右翻页 + 消珠详情条** | 算路后提供 `← / →` 按钮翻看多个方案，下方列出预计总 Combo 与每组消除的颜色图标与颗数 | **强烈保留**：C++ 引擎直接返回 Top-K 多样化路径（如最高 Combo / 最短步数 / 最稳解盾），点击切换预览轨迹 |
| **使用者符石设定模式（`OrbSetting`）** | 悬浮 6×5 透明网格，选中格子后底部改色 + 7 项状态勾选：**拼图盾、无法移动/触碰、优先、保留、起点、终点、锁定设定** | **保留并升级**：支持「点击单格」+「画笔连涂」（标拼图盾快 5 倍）；保留极具巧思的**「锁定设定」**（多回合拼图/红绿灯免重画），并补充现代状态（燃烧/电击/强化） |
| **原地盘面微调校准条（`correctionview`）** | 悬浮条直接切出上下位移、加减宽高、自动校正、重置按钮 | **保留**：叠加半透明 6×5 对齐框线，并增加拖拽四角手柄与按分辨率自动记忆 |
| **试跑模式 + 移动前倒数 + 紧急出口按钮** | 先画线确认再点执行；执行前可选 1~3 秒倒数；独立红色急停按钮 | **保留**：设为默认安全交互流程，急停按钮可直接中止无障碍手势续接链 |
| **护眼/滤色器冲突提示（`CheckScreenFilter`）** | 启动时提示关闭第三方蓝光护眼滤镜，防止识图色偏 | **保留**：增加亮度/夜间护眼模式检测提醒（配合 AI 模型的色偏增强也能大幅缓解） |

### 2.2 转珠与解盾参数体系（神魔老玩家刚需）

旧版在 `page_orbs.xml`、`page_tos.xml` 与 `page_main.xml` 中积累了一套非常贴合神魔之塔实战的参数矩阵，其中多项极有价值：

#### 1. 单属性精细「三元组」规则（水/火/木/光/暗/心 各自独立）
旧版为每种属性横向排布了三个控件，逻辑非常清晰：
- **消几珠（`orbs_combo_type`）**：`一般(3) / 二珠 / 四珠 / 五珠(强化/全攻) / 横排 / 六珠 / 七珠 / 八珠 / 九珠 / 全消`
- **优先权（`PriorityButton` 三态循环）**：点一下依次切换 `一般 → 优先 → 保留`（高效率单键循环，不占空间）
- **消除时机（`orbs_combo_flag`）**：`无 / 首消 / 叠珠`
  - **亮点**：「首消」满足首消盾，「叠珠」则刻意让该属性不在第一波消除而是靠落珠第二波消掉——完美应对神魔经典的**「首消禁某属」**同时兼顾高 Combo / 回血！

#### 2. 边界与切珠策略
- **珠子不足设定颗数时（`orb_not_enough`）**：`消除` vs `保留`（例如设了「消五珠」，盘面只有 4 颗时，是正常消 3 颗还是保留下来下回合凑 5 颗）。
- **四颗以上消除方式（`EliminateType`）**：`最高Combo` / `消最多珠` / `消除一组`。
- **强制切珠（`force_3_orbs`）**：每组 Combo 尽量拆为 3 颗，防止同色黏成大坨导致 Combo 数暴跌。

#### 3. Combo 与首批控制
- **指定 Combo 模式**：`不指定 / 1~8 Combo / 最大Combo / 最大Combo(Turbo)`，并配 **`最快解（First Result）` vs `最佳解（Best Result）`** 切换。
- **首批 Combo 独立控制（`first_batch_combo`）** + **只计首批开关**：精准应对首消 Combo 盾，或避免依赖叠珠。
- **快捷全局目标模式（`mode`）**：`高Combo / 三色 / 四色 / 五色 / 消五珠(单色/多色) / 消六珠 / 消八珠`。

#### 4. 神魔之塔专属机制（`page_tos.xml`）
- **直排模式（升华技！）**：第 1~6 列各自独立开关，每列可选 `消三珠 / 消四珠 / 消五珠`（非常经典的神魔「直排升华剑」触发需求！）。
- **燃烧路径 / 腐蚀路径（轨迹燃烧/黏腐）**：独立设定「**最大碰撞次数（0~10）**」和「**轨迹尾迹长度（Max / 6）**」。
- **无法辨识珠子的兜底策略**：`不处理 / 视为问号珠 / 问号珠 + 风化珠`。
- **常用起点快速约束**：`无 / 左下 / 右下`（配合单格手选起终点形成完整红绿灯支持）。
- **排珠 / 主角技长步数模式**：支持一键切换到高步数上限（20~80 步）并可配置延迟。

#### 5. 算力、手感与预设管理（`page_main.xml`）
- **算力复杂度档位（Beam Width）**：`微(10) / 低(30) / 中(50) / 高(100) / 超(300) / 极(500)` — 玩家无需懂算法就能在「秒出」与「极高 Combo」间权衡。
- **步数滑杆（最高 60 步）** + **8 方向斜转开关** + **移动速度滑杆** + **拟人化转珠开关** + **路径配色（灰阶/彩色）**。
- **10 组自定义设定集（Profile 0~9）**：可自定义名称，一键保存/载入全部规则（AutoDora-NEXT 升级为无限组 Room 预设 + 悬浮窗下拉秒切）。

## 3. 旧版缺陷与必须彻底淘汰的“历史包袱”

| 旧版机制 | 问题根源 | AutoDora-NEXT 彻底革新方案 |
| :--- | :--- | :--- |
| **Root `/dev/input/eventX` & `/dev/uinput` 触控** | 依赖 `su`、关闭 SELinux、`libDeviceScanner.so` 扫描硬件节点，现代未 Root 手机彻底不可用 | 改用标准 **`AccessibilityService` (`dispatchGesture` + `willContinue`)**，抽象 `TouchExecutor` 预留 **Shizuku** |
| **Root 截屏 / 手动截屏目录监听** | 需 Root 读 framebuffer 或靠用户手动按系统截屏键再扫相册 | 改用 **`MediaProjection` 前台服务**，免 Root 一键毫秒级取帧 |
| **硬编码 RGB 区间 + 分辨率坐标表** | 靠 `ColorRange` 硬编码 RGB 与二次采色点，面对现代全面屏、强化珠、种族珠、电击/风化/燃烧/黑白特效全面失效 | 改为**自适应网格校准 + 传统 CV 冷启动 + 端侧轻量多头 CNN（Batch=30）+ 纠错样本回流训练闭环** |
| **跳出游戏暂停（`DummyActivity`）与提权保活** | 早期手机算力弱需强切前台暂停游戏、改 `OOM_ADJ` 防杀进程 | 现代手机 + 多线程 C++20 引擎 300ms 内出解，无需切后台暂停；使用合规前台服务保活 |
| **规则互斥限制** | 旧版 C 引擎在开启 Turbo 或指定 Combo 最快解时，会强制关闭拼图盾、直排模式与燃烧路径 | `AutoDora-NEXT` 采用**可组合约束与评分管线**，拼图盾 + 直排升华 + 燃烧路径 + 首消/叠珠 + 避风化全部自由组合 |
| **10 款游戏杂烩 + 6 家广告 SDK** | 包含大量无关游戏配置与 Vpon/Flurry/Facebook/MoPub 等广告代码 | 专注《神魔之塔》，代码纯净零广告、最小化权限 |

## 4. 对 AutoDora-NEXT 架构的直接增量补强

基于此次旧版拆解，建议立刻将以下 **6 项高价值能力** 纳入 `AutoDora-NEXT` 的数据模型与设计规格中：

1. **属性级规则矩阵**：`RulePreset` 中为 6 种符石各自配备 `(targetOrbCount, priority[RESERVE/NORMAL/HIGH], matchTiming[ANY/FIRST_WAVE/CASCADE_STACK])` 以及全局 `notEnoughPolicy`（不足时消除 vs 保留）与 `forceSplitThree`（强制 3 珠切珠）。
2. **直排升华技约束**：在 `RulePreset` 中增加 `columnRequirements[6]`（每列可独立开启并指定 3/4/5 消），纳入 C++ 引擎评估器。
3. **轨迹燃烧 / 黏腐精细建模**：在 C++ 路径搜索状态中记录**滑动轨迹尾迹窗口**（`trailLength = 6` 或 `unlimited`）与 `maxTrailHurtCount`（允许踩踏次数上限 0~10），精准适配神魔的「轨迹燃烧/腐蚀」。
4. **单格标记补齐「优先 / 保留 / 锁定」**：在 `CellState` 与悬浮编辑网中保留 `CELL_PRIORITY`（指定单颗必消）、`CELL_RESERVE`（指定单颗保留）以及「跨回合锁定标记」开关。
5. **游戏内原地悬浮调参 + Top-K 多方案翻页 + 消珠预览条**：保留旧版最受老玩家好评的悬浮窗工作流。
6. **搜索复杂度档位 + 最快解/最佳解模式**：在 C++ Beam Search 引擎中直接暴露 `beamWidth` 档位（10 ~ 500）与 `earlyStopOnGoal`（满足指定 Combo / 盾牌即早停的最快解模式）。
